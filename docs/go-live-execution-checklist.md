# SHO WEB SUPPORT — 正式販売開始・初回納品チェックリスト

更新日：2026-11-05

## 現状
- 販売導線はブラウザ自動検査済み。GitHub Actions: https://github.com/sho-support/sho-support.github.io/actions/workflows/qa-sales-flow.yml
- 実AIフルオーダー5ページ生成とPC・スマホ確認は、非公開テスト案件「NOVA STATIC」で成功。
- **本番振込先** はまだ未登録。**お客様に渡す独自ドメイン** も未取得・未接続。
- 顧客への正式見積り送信・入金・サイト納品・お客様承認・実ドメインでの公開は、実案件で未検証。未検証箇所を「完成」と呼ばない。

## 1. 運営者が決める・用意するもの
1. 標準URLに使う運営管理ドメインを購入し、更新自動化と支払方法を設定。**購入前にドメイン名、継続費用、所有者名義を確認**する。
2. バンド名などを使ったサブドメインの命名ルールを確定（例：`customer.[運営者所有ドメイン]`）。これは**仮の書式**であり、未取得の名前を契約・名刺・広告に使わない。
3. 通常はお客様本人名義の独自ドメインも選択可能とし、設定費用と毎年の取得・更新実費を正式見積りに含める。
4. 注文管理画面 https://sho-support.github.io/admin/orders.html に管理者としてログインし、「本番用の振込先」を設定。銀行名、支店名、口座種別、口座番号、口座名義を**GitHubのソースやチャットには貼らない**。
5. GitHub Pagesでの **privateリポジトリのPages利用条件** を確認する。GitHub Freeでは原則publicリポジトリが必要。独自ドメイン接続が非公開案件で失敗した場合、勝手に公開せず、有料プラン・別ホスティング・非公開原稿と公開先の分離を再設計する。

## 2. 見積り・入金前（全プラン共通）
1. 注文ページ https://sho-support.github.io/website-order.html の3プランと料金・追加費用・キャンセル条件を見直す。
2. 注文IDを発行したお客様が公式LINEから連携コードを送信。管理者画面で「LINE連携済み」を確認。
3. 管理者が正式見積りで **確定金額・正式URL・そのドメインの所有/更新責任** を確認する。未取得・未管理の仮URLで見積りを送らない。
4. 正式見積りに含む料金・サイトの範囲・追加ページ・契約上の納品条件・返金条件を確認し、LINE送信する。確定URLはシステムに保存され、再送での勝手な変更は拒否される。
5. **送金前にお客様の同意を確認する。** 入金の有無は管理者が銀行明細で確認。APIや画面の自動状態だけでは着金扱いにしない。

## 3. 制作・公開
1. 入金確認後に「入金確認済み → 案件作成・URL送信」を実行し、案件のサイトIDと制作ヒアリングURLを送信。
2. ヒアリング・必要素材を受付後、AI生成→SHO運営確認。写真権利、内容の正確さ、料金、地図、リンク、スマホUI、文字切れ・空欄、メニューを確認。
3. GitHub Pagesの事前公開元`/docs`（プレースホルダー）でDNSとHTTPSを検証。ただしprivateリポジトリのプラン制限に注意。
4. 顧客へ **非公開のレビューURL** を送信し、修正依頼・内容承認を受ける。
5. 公開前検査でHTML全ページのリンク先、写真、JS/CSSの存在、確認用のプライベートURL混入を検査。
6. 正式公開は、**納品URL・HTTPS・CNAME一致・顧客承認** がすべて合格してから実行。
7. 正式公開後、顧客へ公開URL・更新依頼URLを案内。公開した端末以外の端末からも実際に表示を確認する。
8. **名刺・看板・QRコードに載せるのは正式URLの公開/HTTPS確認後のみ。** 領収・契約記録も保管。

## 4. リリース判定
- Go：販売ページ表示・受注・見積り・銀行登録・固定URL確保・認証・制作・顧客承認・本番公開が通し検証済み。
- No-Go：正式ドメインが未取得、振込先未設定、URLの管理者不明、実サイトの初回公開テスト失敗、特商法等の最終確認未完了。
- チャット相談・仮見積りの受付自体は可能だが、**正式URLを確保できないままの入金・納品はしない**。
